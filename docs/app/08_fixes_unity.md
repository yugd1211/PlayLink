### 1.3 방화벽 프로필 선택의 근거 (코디네이터 결정 (d))

- 사실: 이 PC 의 네트워크는 지금 Windows 에 **공용**(프로필 4)으로 등록돼 있고, Unity 에디터에는 공용 프로필의 차단 규칙(`Unity 2022.3.62f2 Editor`, 모든 프로토콜)이 켜져 있습니다. 읽기 스크립트로 다시 확인했습니다.
- 규칙이 효과를 내려면 **지금 활성인 프로필**에 걸어야 합니다. 개인 프로필에만 걸면 이 PC 에서는 아무 일도 일어나지 않습니다. 그래서 프로필은 "지금 프로필 하나"로 두었습니다(도메인/개인/공용 전부가 아님).
- 공용 프로필에 걸면 "공용으로 분류된 다른 모든 네트워크"에도 걸리는 것이 리뷰의 걱정입니다. 그래서 **원격 주소를 지금 대역 숫자로** 한 번 더 좁혔습니다. 다른 대역의 공용 네트워크에서는 열리지 않습니다. 남는 구멍은 "같은 대역 숫자를 쓰는 다른 공용 네트워크"이고, 이것은 창·대화 상자·README 에 그대로 적었습니다.
- 더 좁히는 길(소유자가 고를 것): 네트워크를 '개인'으로 바꾼 뒤 누르기. 창이 그 방법을 안내합니다.
- 설계 범위(이 Unity.exe, TCP, 도구 포트, 로컬 대역)와 같거나 더 좁습니다. 대체 차단 규칙(도구 포트 밖 TCP + UDP 전체)은 "끈 차단 규칙이 막던 것을 계속 막기" 위한 것입니다.

## 4. 설계 문서 16장에 넣을 항목 (최종 단계가 합칠 것)

1. **닫기 코드 4409**: 같은 앱(`did`)이 같은 종류의 소켓을 새로 열면 서버가 옛 소켓을 4409 로 닫는다. 앱은 4409 로 재접속하지 않는다.
2. **쓰기 제한과 닫기**: 모든 소켓 `SendTimeout` 3초. 메인 스레드의 닫기는 기다리지 않으며, 상대가 읽지 않으면 닫기 프레임 없이 끊는다. 거절할 때는 닫기 프레임 뒤 남은 입력을 잠깐 읽어 버린다.
3. **루프백 규칙**: Origin 은 `localhost`/`127.0.0.1` + **들어온 포트**. HTTP 는 Host 가 `localhost`/`127.0.0.1`(또는 없음)일 때만.
4. **한도**: 인증 전 연결 주소별 6(전체 16), 인증 대기 8 은 리스너별, `/apk` 동시 3·주소당 1·전체 120초.
5. **대기실 문구**: Play 중에 화면 전송만 멈춘 경우의 문구 추가.
6. **방화벽**: 허용 규칙의 원격 주소는 지금 대역 숫자, 프로필은 지금 프로필 하나. 기록과 규칙 이름은 실행 파일별. 기록을 먼저 쓴다. 결과 파일과 종료 코드로 실패를 알린다. 출력만 모드.
7. **착륙 페이지**: 패키지와 스킴은 서버가 채운다. 연결 값은 형식 검사 뒤 다시 조립한다.
8. **USB 버튼**: 대상이 둘 이상이면 멈춘다. 설치 제한 120초. 연결은 앱의 `.Diag` 입구로.
9. **자리 규칙 설명**(동작 변경 없음): 선호가 없으면 앱이 페이지보다 우선(3.5 규칙 3). "자동 재접속은 뺏지 않는다"는 선호가 있을 때의 말이다.
10. **결정이 필요한 것**: m13(확장 채널을 처음 쓸 때 닫기·루프백·caps 를 계약으로), m18(사설 대역 밖 주소를 고를 수 있게 할지).

## 8. 마지막 확인 (PC 시계 02:41)

- `08_interop_notes.md` 를 끝내기 전에 다시 읽었습니다. 안드로이드 쪽 답: 앱이 4409 를 받으면 재접속하지 않고 멈추게 고침, 대기실 `msg` 는 그대로 보임, `.Diag` 입구의 `--es t` 는 release 빌드에서도 받게 바꿈, `App~` 의 APK 를 같은 버전 번호(0.1.2, 3)로 한 번 더 바꿈(sha256 `a07bad64…`).
- 그 **마지막 APK 로 [USB 로 앱 설치] → [USB 로 연결]을 다시 실행**했습니다: `Success`, 설치된 버전 0.1.2 (3), 앱 재생 59fps, 창 "연결됨: sdk_gphone64_x86_64 USB, 보는 중". QR 주소 경로와 `withapp` 은 그 전 APK(sha `4c21d699…`)로 본 것이고 마지막 APK 로는 다시 하지 않았습니다.
- 앱이 **사설 대역 주소만 받는다**는 안드로이드 쪽 메모(3번)는 m18 을 받지 않은 것과 맞습니다: 사설 대역 밖 주소를 Unity 창에서 고를 수 있게 해도 앱이 거절합니다.
- 안드로이드 쪽 메모의 시각(02:45, 02:55)은 이 PC 의 시계(지금 02:41)보다 앞서 있습니다. 순서는 맞고 시각은 근거로 쓰지 마세요.
- 앱의 새 4409 처리("앱을 닫았다가 다시 여세요"로 멈춤)는 **기기에서 일으켜 보지 않았습니다**(양쪽 모두). 서버가 4409 를 보내는 것은 스크립트로만 확인했습니다. 실제 폰에서 "USB 로 보다가 QR 로 전환" 같은 때 앱이 멈춤 화면으로 가지 않는지 소유자 확인 항목에 넣어 주세요.
- 에디터 상태에 덧붙임: Play 중에 도메인 리로드를 여러 번 했기 때문에 **게임 쪽 스크립트가 매 프레임 오류를 내고 있습니다**(`BattlePassManager.GetCurrentSeasonProgress` 의 NullReferenceException, `TimeManager.OnDisable`). 도구의 오류가 아니라 게임이 Play 중 리로드를 견디지 못하는 것(README 5장에 있는 알려진 일)이고, 화면 전송은 계속 됩니다. **Play 를 한 번 껐다 켜면 없어집니다.** 게임을 조작하지 말라는 조건 때문에 제가 Play 를 끄지는 않았습니다. `[GVR]` 로 시작하는 오류는 콘솔에 없습니다.
