## 2. 차단과 주요

### B1 (차단) 기존 도구의 자동 adb 가 실제 폰을 대상으로 삼습니다

- 자리: `GameViewRemoteAdb.cs:98~122`(`AutoReverseAsync`), `:129~171`(`ReversePreferUsb`), `:78~94`(`RefreshStatusAsync`), `:398~439`(`ListReadyDevices`: 준비된 기기 전부). 부르는 곳: `GameViewRemote.cs:373~376`(서버 Start 마다), `GameViewRemoteWindow.cs:42~55`(창이 열려 있으면 주기적으로). 새 코드가 Start 를 자동으로 부르는 곳: `GameViewRemoteHost.cs:134~137`, `:327~330`, `:397~401`.
- 사실: 가상 기기 제한(`EMULATOR_ONLY`)은 `GameViewRemoteAppAdb.cs:15, 171` 에만 있습니다. 기존 경로에는 없습니다. 명령마다 `-s <일련번호>` 는 붙지만 그 일련번호가 폰일 수 있습니다.
- 실패 시나리오: 소유자가 충전하려고 폰을 USB 로 꽂습니다(USB 디버깅은 이미 허용돼 있음). ① 창이 열려 있으면 몇 초마다 `adb -s R3CW70LJ2VP reverse --list`, 서버가 돌고 있으면 `adb -s R3CW70LJ2VP reverse tcp:7300 tcp:7300`(repair). ② Start 가 켜져 있으면 Play 를 누를 때와 Play 중 재컴파일 때마다 `reverse` 가 폰에 걸립니다. 앞단이 생기면서 Start 가 자동으로 불리는 횟수가 늘었습니다. ③ 누군가 창의 무선 [연결]에 한 번 성공하면 `Window.cs:44~48` 이 주소를 다시 저장해, 다음 Start 부터 `adb connect <폰 주소>` 가 되살아납니다. 브리프 3.4 는 폰에 대한 adb 명령 전부를 금지합니다.
- 지금 안 터지는 이유: 폰이 뽑혀 있고, U1 이 EditorPrefs `GVR_WirelessAddress` 를 손으로 비웠기 때문입니다(코드가 아니라 이 PC 의 상태).
- 원하는 수정: 기기 고르기를 한곳으로 모읍니다. `GameViewRemoteAdb.ListReadyDevices` 가 같은 제한(시험 기간에는 `emulator-` 만)을 적용하고, 제한이 켜져 있는 동안 `AutoReverseAsync` 의 `Connect(savedWirelessAddress)` 를 건너뜁니다. 제한 값은 `AppAdb` 의 상수와 하나로 합칩니다(둘이 따로 놀면 한쪽만 풀립니다). 덧붙여, 앞단이 부른 `GameViewRemote.Start()`(QR 경로)에서는 자동 `reverse` 를 하지 않는 편이 맞습니다. QR 연결에는 adb 가 필요 없습니다.

### M1 (주요) Wi-Fi 상대가 조용히 사라지면 에디터 메인 스레드가 멈출 수 있습니다

- 자리: `GameViewRemoteServer.cs:915~937`(`WriteMessage`: `lock (connection.stream)` 안에서 막히는 `Write`), `:163~189`(`Stop` 이 메인 스레드에서 연결마다 `SendClose`), `:881~897`(`CloseWith`, `CloseTagged`). 넘겨받은 소켓에 `SendTimeout` 을 거는 곳이 없습니다(폴더 전체에서 `GameViewRemoteFiles.cs:180` 한 곳뿐).
- 실패 시나리오: 앱이 Wi-Fi 로 영상을 받는 중에 폰이 범위를 벗어나거나 잠들어 FIN 없이 사라집니다. 전송 스레드는 150ms 역압이 걸리기 전에 프레임 여러 장(장당 약 12KB)을 써서 소켓 버퍼를 채우고 `Write` 에서 막힙니다. 이때 소유자가 Play 를 끄거나, 스크립트를 저장하거나, [Stop] 이나 [새 QR 발급]을 누릅니다. 메인 스레드가 `SendClose` → `lock (connection.stream)` 에서 기다립니다. Windows 가 재전송을 포기할 때까지(대략 10초 안팎, 재지 않았습니다) Unity 가 멈춥니다.
- 예전부터 있던 구조지만, 예전 상대는 같은 PC 의 adb 서버였습니다. 무선이 기본 경로가 되면서 드러나는 문제입니다.
- 원하는 수정: ① 넘겨받을 때와 루프백 수락 때 `client.SendTimeout` 을 겁니다(2~3초). ② `Stop`, `CloseWith` 는 닫기 프레임을 쓰려고 기다리지 않습니다: `Monitor.TryEnter(connection.stream, 50)` 이 안 되면 프레임 없이 `client.Close()`(다른 스레드의 막힌 `Write` 가 풀립니다). ③ 같은 이유로 `GameViewRemoteHost.KickLobby`(`Host.cs:529~548`)와 `GameViewRemoteWs.TryWriteClose`(`Ws.cs:185~198`)도 메인 스레드에서 잠금을 기다리지 않게 합니다.
- 확인 방법(가상 기기로 가능): 영상 수신 중인 클라이언트의 수신을 멈춘 채(node 소켓 `pause()`) Unity 에서 Play 를 끄고 걸린 시간을 잽니다.

### M2 (주요) 같은 앱의 영상 소켓이 둘이 되면 H.264 가 꺼집니다

- 자리: `GameViewRemoteServer.cs:820~842`(`SingleH264Client`: 대기가 아닌 영상 연결이 둘이면 null → MJPEG), `GameViewRemoteSeats.cs:90~119`, `:313~330`(무리 단위로만 자리를 정함. 같은 무리의 옛 소켓을 닫지 않음).
- 실패 시나리오: Wi-Fi 가 잠깐 끊기거나 AP 를 옮깁니다. 앱은 끊김을 알아채고 곧바로 다시 붙지만, 서버에는 옛 소켓이 반쯤 열린 채 남습니다(서버 쪽에 keepalive 도 타임아웃도 없음). 같은 `did` 라 둘 다 보는 무리이고 둘 다 대기가 아닙니다. 서버는 MJPEG 로 떨어지고, 앱은 JPEG 를 그리지 않으므로 2초 뒤 "PC가 H.264 를 보낼 수 없습니다" 상태가 됩니다. 옛 소켓이 쓰기 실패로 죽을 때까지(M1 과 같은 시간) 이어집니다.
- 설계가 자리 규칙으로 없애려던 "영상 클라이언트가 2개면 둘 다 MJPEG"(브리프 3장)가 무선 재접속에서 그대로 남아 있습니다. 요구사항 11(무선이 1순위)에 직접 걸립니다.
- 원하는 수정: `Seats.OnJoin` 에서 앱 무리(`session != null`)에 같은 종류(영상/입력)의 연결이 이미 있으면 옛 것을 닫습니다(새 것이 이김). 페이지 무리는 지금처럼 둡니다(범위 밖).
- 확인 방법: 같은 `did` 로 영상 소켓 둘을 열고 두 번째가 H.264 를 받는지 봅니다(`hosttest.js` 에 시험 추가).

### M4 (주요) [USB 로 앱 설치], [USB 로 연결]은 한 번도 실행되지 않았고, 설치는 10초 제한에 걸립니다

- 자리: `GameViewRemoteAppAdb.cs:28~72`(설치), `:75~102`(연결), `GameViewRemoteAdb.cs:17`(`ADB_TIMEOUT_MS = 10000`), `:484~488`(넘으면 프로세스를 죽임).
- 사실: 서버 부록 5장이 두 버튼을 실행하지 않았다고 적었습니다. 이 PC 에서는 방화벽을 열기 전까지 QR 설치가 되지 않으므로(설계 10.4) 이 버튼이 첫 설치의 유일한 길입니다.
- 실패 시나리오: 3.5MB APK 설치에 Play 프로텍트 검사가 붙어 10초를 넘깁니다. `Run` 이 adb 를 죽이고 창에는 "10초 안에 끝나지 않았습니다"가 나옵니다. 설치는 됐을 수도 안 됐을 수도 있습니다.
- 그 밖: `PickDevice`(`:143~`)는 조건에 맞는 첫 기기를 말없이 고릅니다(기기가 둘이면 어느 쪽인지 묻지 않음). `AppAdb.RunInBackground` 는 기존 `runLock` 을 잡지 않아 창의 상태 확인과 adb 가 동시에 돕니다(설계 9.4 M8-d 의 전제와 다름).
- 원하는 수정: `Run` 에 제한 시간 인자를 두고 설치는 60~120초. 가상 기기에서 두 버튼을 실제로 눌러 확인합니다(장치 랩이 READY 일 때). 기기가 둘 이상이면 고르게 하거나 목록을 보이고 멈춥니다.

## 4.1 부록의 주장과 증거의 차이

## 5. 고칠 순서

1. **B1**: 기존 adb 경로에 같은 기기 제한을 넣고, 제한 중에는 저장된 주소로 `adb connect` 하지 않기. 앞단이 부른 Start 에서는 자동 `reverse` 생략.
2. **M1**: `SendTimeout` 과, 메인 스레드가 쓰기 잠금을 기다리지 않는 닫기.
3. **M2**: 같은 앱 무리의 같은 종류 옛 소켓 닫기 + `hosttest.js` 에 시험 추가.
4. **M3**: a(프로필 이름과 공용 경고), b(백업 먼저), c(`$prof`), e(실패 표시), f(출력만 하는 실행). d 는 그다음.
5. **M4**: 설치 제한 시간, 가상 기기에서 두 버튼 실행 확인.
6. m1, m2, m5(작고 효과가 분명한 것).
7. 설계 9.9 의 페이지 회귀 확인(`wsclient.js` 네 가지)을 PC 에서 돌리고 결과를 서버 부록에 추가.
8. m7, m8, m9, m10(문서와 `.gitignore`, README).
9. 나머지 작음.
