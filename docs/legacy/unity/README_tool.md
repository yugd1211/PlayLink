# Game View Remote 사용 가이드

Unity 에디터에서 Play 중인 **Game 뷰 화면을 안드로이드 폰에 띄우고**, 폰 터치로 게임을 조작하는 도구입니다.
빌드 없이 실기기 터치감으로 바로 테스트할 수 있습니다. Unity Remote 5를 대신합니다.

폰에서 보는 방법은 두 가지입니다.

| 방법 | 연결 | 폰에 필요한 것 | 이럴 때 |
|---|---|---|---|
| **앱 + QR (0장)** | 같은 Wi-Fi. 창에서 Start → QR 을 폰 카메라로 찍기 | Game View Remote 앱(QR 로 설치) | 평소. 주소나 포트를 입력하지 않습니다 |
| Chrome 페이지 (2장~) | USB 케이블(adb reverse) 또는 무선 adb | Chrome 브라우저 | 앱을 깔 수 없을 때, 예전 방식 그대로 |

- Game 뷰 **원본 해상도** 그대로 보냅니다. 에디터 fps만큼(이 PC 약 60fps) 보냅니다.
- **H.264(하드웨어 인코딩)** 를 쓰려면 ffmpeg가 필요합니다(1장). 앱은 H.264 만 표시합니다. Chrome 페이지는 ffmpeg 가 없으면 자동으로 MJPEG(프레임별 JPEG)로 받습니다.
- 멀티터치를 지원하고, UI 버튼과 게임플레이 터치가 모두 실기기처럼 동작합니다.
- 에디터 전용입니다. 빌드에 포함되지 않고, 게임 코드를 바꾸지 않습니다.

> 개발 문서(구조, 프로토콜, 설계 이유): `docs/GameViewRemote/GameViewRemote_Development.md`

---

## 0. 가장 쉬운 방법: QR 로 연결 (앱)

1. 메뉴 **Tools > Game View Remote > Window** 로 창을 엽니다.
2. 맨 위의 **Start** 를 누릅니다. Play 를 누르지 않아도 됩니다. 창에 **QR** 이 나타납니다.
3. 폰과 PC 가 **같은 Wi-Fi(같은 공유기)** 인지 확인하고, 폰의 **기본 카메라**로 QR 을 비춘 뒤 뜨는 링크를 누릅니다.
4. 처음이면 폰 브라우저에 설치 안내가 나옵니다. **[앱 설치(APK 받기)]** 로 앱을 깔고 **[여기를 눌러 연결]** 을 누릅니다. 앱이 이미 있으면 **[앱으로 열기]** 만 누릅니다.
5. Unity 에서 **Play** 를 누르면 폰에 게임 화면이 나옵니다. 다음부터는 폰에서 앱만 열면 자동으로 다시 연결됩니다(QR 을 다시 찍지 않음).

창에 보이는 것:

| 항목 | 뜻 |
|---|---|
| **Start / Stop** | Start 를 누르면 연결을 받기 시작하고 QR 이 생깁니다. Stop 하면 연결을 모두 끊고 QR 을 닫습니다. Start 상태는 스크립트를 다시 컴파일해도 유지됩니다 |
| 상태 / 연결된 기기 | 지금 어떤 기기가 붙어 있고, 누가 화면을 보는 중(●)이고 누가 기다리는 중(○)인지. **화면은 한 번에 한 기기에만 나갑니다.** 다른 기기에서 보려면 그 기기 화면의 **[여기서 보기]** 를 누릅니다 |
| QR | 폰 카메라로 찍는 그림. 폰이 연결되면 저절로 접히고 **[QR 보기]** 로 다시 펼칩니다. **[QR 크게]** 는 멀리서 찍을 때 씁니다 |
| 이 PC 주소 | PC 에 네트워크가 여러 개일 때만 고르는 목록이 나옵니다. 보통은 "자동으로 고르기" 그대로 둡니다. 폰에서 연결이 안 되면 폰과 같은 공유기 쪽 주소를 골라 봅니다(직접 입력하는 곳은 없습니다) |
| **새 QR 발급** | 지금 QR 을 못 쓰게 만들고 새 QR 을 만듭니다. 연결돼 있던 폰은 끊기고 새 QR 을 다시 찍어야 합니다. QR 이 화면 공유나 사진으로 다른 사람에게 알려졌을 때 누릅니다 |
| QR 이미지 저장 | 지금 QR 을 `Temp/GameViewRemote/qr.png` 로 저장합니다. 이 그림을 가진 사람은 접속할 수 있으니 함부로 보내지 마세요 |
| Windows 방화벽 | 폰에서 QR 을 찍었는데 페이지가 열리지 않으면 대개 Windows 방화벽이 막은 것입니다. 창이 상태와 **지금 네트워크의 프로필(개인/공용)** 을 알려 주고, **[방화벽 허용…]** 을 누르면 무엇을 바꾸는지 먼저 보여 준 뒤 Windows 가 "이 앱이 디바이스를 변경하도록 허용하시겠어요?" 를 **한 번** 묻습니다. [예] 를 누르면 끝납니다(PC 관리자 권한 필요). **[되돌리기]** 로 원래대로 돌립니다. **[다시 확인]**, **[연결 점검]** 은 아무것도 바꾸지 않습니다. 자세한 범위는 아래 "방화벽 허용이 여는 범위" |
| QR 이 안 될 때: USB | 폰을 USB 로 꽂고 **[USB 로 앱 설치]**, **[USB 로 연결]**. 방화벽을 바꾸지 않아도 됩니다(USB 디버깅 필요, 2장). **지금은 가상 기기에만 동작합니다**(아래 "USB 버튼을 실제 폰에 쓰기") |
| Unity 를 켤 때 자동으로 Start | 이 프로젝트를 열 때마다 Start 상태로 시작합니다. **이 프로젝트에만** 적용됩니다 |

알아 둘 점:

- **Play 중에 폰을 USB 로 꽂으면 Unity 가 그 폰에 `adb reverse` 를 겁니다.** 예전부터 있던 자동 연결이고(USB 의 Chrome 페이지와 [USB 로 연결]이 이것으로 동작), 폰의 설정이나 파일은 바꾸지 않으며 폰의 `localhost:포트` 를 이 PC 로 잇기만 합니다. 원하지 않으면 Play 중에는 폰을 꽂지 않거나 폰의 USB 디버깅을 끄세요. 무선 adb 주소를 저장해 두었으면 서버가 켜질 때마다 그 주소로 `adb connect` 도 시도합니다(지우려면 창의 무선 adb 구역에서 주소를 비움).
- **[Stop] 은 전부 멈춥니다.** QR 연결뿐 아니라 USB 의 Chrome 페이지로 보내던 화면 전송도 같이 꺼집니다. Chrome 페이지만 다시 쓰려면 "화질과 고급 설정"의 예전 Start 를 누르세요. 반대로 [Start] 가 켜진 채 예전 "화면 전송 중지"만 누르면 앱은 "Unity 에서 화면 전송이 멈춰 있습니다"로 기다립니다.
- **QR 을 찍은 사람은 누구나** 이 PC 의 게임 화면을 보고 조작할 수 있습니다. 회사나 집 Wi-Fi 에서만 쓰고 공용 Wi-Fi 에서는 쓰지 마세요.
- QR 은 PC(프로젝트)마다 다르고, **[새 QR 발급]** 을 누르거나 프로젝트의 `Library` 폴더를 지우기 전에는 바뀌지 않습니다. PC 의 주소가 바뀌면(다른 Wi-Fi) QR 그림은 새로 그려지고, 폰은 QR 을 한 번 다시 찍으면 됩니다.
- 게임 화면은 **Play 중에만** 나갑니다. Play 전에는 폰에 "Unity 에서 Play 를 누르면 화면이 나옵니다"가 보입니다.
- 설정이 저장되는 곳: QR 연결의 설정(자동 Start, 고른 주소)은 **프로젝트별** `UserSettings/GameViewRemote.json`, QR 의 비밀 값은 `Library/GameViewRemote/secret.json`(저장소에 올라가지 않음), 화질 같은 나머지 설정은 예전처럼 **PC 공통**(EditorPrefs)입니다.

폰 화면에 나오는 글(창의 글과 같은 뜻입니다):

| 폰에 보이는 글 | 어디서 | 뜻과 할 일 |

### 앱 파일(APK)을 도구에 넣기 / 새 버전으로 바꾸기

QR 로 설치되는 앱은 이 폴더의 `App~/GameViewRemote.apk` 이고 버전은 옆의 `App~/app.json` 입니다(APK 는 `.gitignore` 의 `*.apk` 때문에 커밋되지 않습니다).
앱 프로젝트(`GameViewRemoteApp`)에서 아래 명령이 빌드하고 이 자리로 복사합니다. Unity 를 다시 시작하거나 컴파일할 필요가 없습니다.

```powershell
cd C:\Users\dbrud\Developemnt\SeePlay\GameViewRemoteApp\android
.\build.ps1 -Publish                 # 빌드 + dist 폴더 + App~ 복사
..\tools\publish-to-unity.ps1        # 이미 빌드된 dist 의 것을 복사만
```

창의 QR 옆에 "설치될 앱: 0.1.2 (3)" 처럼 버전이 보이면 들어간 것입니다.

### USB 버튼을 실제 폰에 쓰기 (지금은 꺼져 있음)

시험 기간에는 **[USB 로 앱 설치] [USB 로 연결] [연결 점검]** 이 PC 의 안드로이드 가상 기기(일련번호 `emulator-…`)에만 명령을 보내고, 실제 폰이 꽂혀 있어도 건드리지 않습니다(이 세 버튼만 그렇습니다. 위 "알아 둘 점"의 자동 `adb reverse` 는 예전 그대로 실제 폰에도 걸립니다).
대상 기기가 둘 이상이면 고르지 않고 멈춰 목록을 보여 줍니다. 하나만 남기고 다시 누르세요. 모든 명령은 일련번호를 지정해(`adb -s <일련번호>`) 보냅니다.
[USB 로 연결]은 앱의 adb 전용 입구(`kr.co.seeplay.gvr/.Diag`)로 연결 값을 넘깁니다. 이 입구는 지금 도구에 든 시험용 빌드(build `proto`)에만 있습니다.
실제 폰에서 쓰기로 정했으면 `GameViewRemoteAppAdb.cs` 맨 위의 `private const bool EMULATOR_ONLY = true;` 를 `false` 로 바꾸고 저장합니다(Unity 가 다시 컴파일하면 적용).
QR 로 하는 설치와 연결은 이 설정과 무관하게 실제 폰에서 동작합니다.

### 방화벽 허용이 여는 범위

**[방화벽 허용…]** 이 넣는 허용 규칙은 하나입니다: **이 Unity.exe, 들어오는 TCP, 도구 포트 하나(기본 7300), 보내는 쪽은 지금 붙어 있는 네트워크의 주소 대역(예: `192.168.25.0/255.255.255.0`), 지금 네트워크의 프로필 하나.**

- Unity 에디터에 걸려 있던 "차단" 규칙(Windows 가 처음 물었을 때 [취소]를 누르면 생김)은 끄기만 하고 지우지 않습니다. 대신 **도구 포트 밖의 TCP 와 UDP 전체를 막는 규칙**을 넣어, 다른 포트는 계속 막힙니다.
- **네트워크가 '공용'으로 등록돼 있으면** 허용 규칙도 공용 프로필에 걸립니다. 주소 대역으로 한 번 더 좁혔기 때문에 주소 대역이 다른 카페·공항 Wi-Fi 에서는 열리지 않지만, 같은 대역(192.168.0.x 처럼 흔한 것)을 쓰는 다른 공용 네트워크에서는 열립니다. 집이나 사무실이면 **Windows 설정 > 네트워크 및 인터넷 > 연결 속성 > 네트워크 프로필 유형을 '개인'** 으로 바꾼 뒤 누르는 편이 좋습니다. 창과 확인 대화 상자가 지금 프로필을 알려 줍니다.
- 포트, Unity 버전(실행 파일 경로), 네트워크(주소 대역이나 프로필)가 바뀌면 다시 눌러야 합니다. 창이 "허용 규칙이 다른 네트워크용입니다"라고 알려 줍니다.
- 끈 규칙의 이름은 `%LOCALAPPDATA%\GameViewRemote\firewall-backup-<실행 파일 표시>.json` 에 **규칙을 바꾸기 전에** 적어 두고, **[되돌리기]** 가 넣은 규칙을 지우고 그 규칙들을 다시 켭니다. Unity 버전이 여러 개여도 서로의 규칙과 기록을 건드리지 않습니다.
- 관리자 확인을 취소하거나 적용이 실패하면 창에 "적용하지 못했습니다"가 보입니다.
- **누르기 전에 무엇이 바뀌는지 보려면** 메뉴 `Tools > Game View Remote > Firewall Dry Run (출력만)`: 관리자 권한 없이 같은 스크립트를 "출력만" 모드로 돌려 실행될 변경을 Console 에 `WOULD: …` 줄로 보여 줍니다. 아무것도 바꾸지 않습니다.

### 없어진 것: "Wi-Fi 접속 허용" 토글

예전 창에 있던 **"Wi-Fi 접속 허용"** 토글(폰 Chrome 에서 `http://<PC IP>:7300/` 을 직접 여는 방법)은 **없앴습니다.**
그 방법은 인증이 없어 같은 네트워크의 누구나 주소만 알면 화면을 보고 조작할 수 있었습니다.

| 예전 | 지금 대신 쓰는 것 |
|---|---|
| "Wi-Fi 접속 허용"을 켜고 폰 Chrome 에서 PC IP 로 접속 | **QR(앱)**: 0장. QR 을 찍은 기기만 접속됩니다 |
| 방화벽을 관리자 PowerShell 명령으로 열기 | 창의 **[방화벽 허용…]** 버튼 |
| Chrome 페이지를 무선으로 쓰기 | **무선 adb**(2.3절). 폰은 `http://localhost:7300/` 을 엽니다 |

### 2.3 Chrome 페이지를 무선으로 쓸 때: 무선 adb

PC가 폰에 adb로 무선 접속하고 그 위에 `adb reverse`를 겁니다. 폰은 USB와 똑같이 `http://localhost:7300/`을 엽니다. PC로 들어오는 연결이 없어서 Windows 방화벽을 바꿀 필요가 없습니다. PC와 폰은 같은 Wi-Fi에 있어야 합니다.

- **A-1. USB로 한 번 연결해서 전환 (가장 쉬움, 모든 안드로이드)**
  1. 폰을 USB로 연결합니다(2.2).
  2. Game View Remote 창 > 접속 > 무선에서 **"USB 폰을 무선으로 전환"**을 누릅니다. 결과 칸에 "무선 연결됨"이 나오면 됩니다.
  3. **USB 케이블을 뽑습니다.** 이후는 "폰에서 열기" 등 USB와 똑같이 씁니다.
  - 폰을 **재부팅하면 풀립니다.** 다시 USB로 연결해 한 번 더 누르세요.
- **A-2. Android 11 이상: 무선 디버깅 (케이블 없이)**
  1. 폰 **설정 > 개발자 옵션 > 무선 디버깅**을 켜고 **페어링 코드로 기기 페어링**을 누릅니다.
  2. 창의 "페어링" 칸에 폰에 나온 `IP:포트`와 6자리 코드를 넣고 **페어링**을 누릅니다(처음 한 번).
  3. 무선 디버깅 화면 위쪽 **"IP 주소 및 포트"**(페어링 포트와 다름)를 "주소" 칸에 넣고 **연결**을 누릅니다.
- 마지막으로 연결한 주소를 기억해 두고, **Start 때 연결된 기기가 없으면 자동으로 다시 연결**한 뒤 `adb reverse`를 겁니다.
- 끊으려면 "끊기"를 누릅니다.
- Wi-Fi(adb 무선)는 USB보다 대역폭이 훨씬 적습니다(이 PC/공유기 2.4GHz 실측 약 8~15Mbps, USB 176Mbps). **H.264를 켜 두면** 원본 해상도 약 3~6Mbps라 무선에서도 부드럽습니다(실측: 29~30fps 로비 = 화면 내용 속도, 터치 → 화면 평균 68~77ms). MJPEG로만 써야 하면 전송 해상도 50% + JPEG 40~60으로 낮추세요.
- 5GHz Wi-Fi가 있으면 그쪽에 연결하는 것이 좋습니다(2.4GHz는 혼잡하고 느림).

> 같은 Wi-Fi 에서 PC 주소로 Chrome 페이지를 직접 여는 방법("Wi-Fi 접속 허용")은 없앴습니다. 같은 Wi-Fi 로 바로 붙는 것은 QR + 앱(0장)입니다.

## 4. 사용 순서

### 앱 + QR

0장을 보세요. Start → QR 찍기 → Play 입니다.

### Chrome 페이지, USB

1. 폰을 USB로 연결합니다.
2. Unity에서 **Play**를 누릅니다.
3. Game View Remote 창 맨 위의 **Start**를 누릅니다(이미 Start 상태거나 자동 시작을 켰으면 생략). QR 없이 페이지만 쓰려면 "Chrome 페이지로 연결" 구역의 **"화면 전송 시작 (Play 중)"** 을 눌러도 됩니다. 기기가 1대면 `adb reverse`가 자동으로 됩니다.
4. "Chrome 페이지로 연결" 구역의 **"폰에서 열기"** 버튼을 누릅니다. `adb reverse` 후 폰 Chrome에서 `http://localhost:7300/`이 열립니다.
   - 직접 열어도 됩니다: 폰 Chrome에서 **`http://localhost:7300/`**.
   - 창 맨 위에 USB 경고(기기 없음, unauthorized, reverse 없음)가 있으면 그것부터 처리합니다.
5. "탭하면 전체 화면으로 시작합니다"를 탭합니다. 이제 폰으로 게임을 조작합니다.

- Play를 껐다 켜도 폰 페이지는 **자동으로 다시 접속**합니다(자동 시작을 켠 경우). 페이지를 다시 열 필요가 없습니다.
- **USB를 뽑았다 꽂으면 `adb reverse`가 풀립니다.** 창에 "adb reverse가 없습니다" 경고가 뜨면 "폰에서 열기"나 "adb reverse" 버튼을 다시 누르세요.
- 자주 쓰면 폰 Chrome에서 이 주소를 **홈 화면에 추가**해 두면 편합니다.

### 폰 페이지 버튼

| 버튼 | 기능 |
|---|---|
| 가운데 **여기서 보기** | 다른 기기(앱)가 화면을 보고 있어 이 페이지가 기다리는 중일 때만 나옵니다. 누르면 화면이 이 페이지로 옵니다(그 기기는 기다리는 상태가 됨) |
| 오른쪽 위 `i` | 디버그 표시 켜기/끄기(fps, Mbps, 해상도, RTT, 터치→화면 지연) |
| 오른쪽 위 `⛶` | 전체 화면으로 돌아가기 |
| 주소 뒤 `?debug=1` | 처음부터 디버그 표시를 켠 상태로 열기(`http://localhost:7300/?debug=1`). 디버그 표시가 켜져 있으면 검은/손상 프레임 픽셀 검사를 10장에 1장(평소 30장에 1장) 합니다 |
| 주소 뒤 `?desync=1` | 비교용: 검은 화면 수정 **전** 그리기 방식으로 엽니다. 평소에는 쓰지 마세요 |
| 주소 뒤 `?sched=0` | 비교용: 표시 일정을 끄고 도착 순서대로 그립니다 |
| 주소 뒤 `?worker=0` | 비교용: 영상을 예전처럼 메인 스레드에서 받습니다. 탭할 때 누른 시간만큼 화면이 멈춥니다. 검은/손상 프레임 픽셀 검사는 이 경로에서만 됩니다 |
| 주소 뒤 `?buffer=50` | 무선처럼 가끔 늦게 오는 링크에서 고르게 보려고 표시를 50ms 늦춥니다(지연이 그만큼 늘어남). 숫자는 ms |

## 5. 알아 둘 점

- **게임 화면은 Play 중에만 나갑니다.** Chrome 페이지가 붙는 서버는 Play 를 끝내면 자동으로 닫힙니다. QR 연결(Start)은 Play 밖에서도 열려 있어 앱이 미리 붙어 기다릴 수 있습니다.
- **화면은 한 번에 한 기기에만 나갑니다.** 앱과 Chrome 페이지가 함께 붙으면 한쪽은 "다른 기기가 보고 있습니다"로 기다리고, **[여기서 보기]** 를 누른 쪽으로 옮겨집니다. 마지막으로 [여기서 보기]를 누른 쪽(또는 QR 을 찍은 앱)이 기억되어, 그쪽이 다시 붙으면 자동으로 되찾습니다. **아직 아무도 고른 적이 없으면 앱이 우선입니다**: 앱이 붙는 순간 보고 있던 Chrome 페이지는 대기로 바뀌고, 페이지에서 [여기서 보기]를 누르면 돌아옵니다.
- 같은 폰의 앱이 연결을 새로 열면(전환, 재접속) 서버는 그 폰의 옛 연결을 닫습니다(닫기 코드 4409). 화면은 새 연결로 이어집니다.
- **Unity가 다른 프로그램 뒤에 있어도 됩니다.** 원격 접속 중에는 UI 버튼이 포커스 없이도 눌리게 해 두었습니다. Unity 창은 최소화하지 마세요.
- **Play 중 스크립트를 고치면** 서버는 다시 열리지만, 게임이 리로드를 견디지 못할 수 있습니다. 스크립트를 고친 뒤에는 Play를 다시 시작하세요.
- **보안:** Chrome 페이지가 붙는 서버는 이 PC 안(127.0.0.1)에서만 열려 USB(adb reverse)나 무선 adb 로만 접속됩니다. 같은 Wi-Fi 에서 들어오는 연결은 QR 을 찍은 기기만 받습니다(QR 안의 비밀 값으로 서로 확인). 다만 연결된 뒤의 영상과 터치는 암호화되지 않으므로 공용 Wi-Fi 에서는 쓰지 마세요.
- 원격 접속 중에는 에디터의 "터치를 마우스로 흉내 내기"(`Input.simulateMouseWithTouches`)를 끕니다. 그래서 에디터 전용 마우스 입력 경로가 실기기와 다르게 점프를 일으키지 않습니다. 접속이 끊기면 원래 값으로 돌아갑니다.

|---|---|
| 폰에서 페이지가 안 열려요(`localhost`) | ① Unity가 Play 중이고 창에 `Running 예`인지 ② 창 맨 위에 USB 경고가 없는지(있으면 "폰에서 열기" 또는 "adb reverse") ③ `adb devices` 결과에 기기가 `device`로 나오는지 |
| `adb devices`에 `unauthorized`가 떠요 | 폰 화면의 USB 디버깅 허용 창에서 허용합니다. 창이 없으면 **개발자 옵션 > USB 디버깅 권한 승인 취소** 후 케이블을 다시 꽂습니다. |
| `adb devices`에 아무것도 없어요 | 케이블이 충전 전용이 아닌지, USB 디버깅이 켜졌는지 확인합니다. 다른 adb(Android Studio 등)가 동시에 돌고 있으면 그 프로그램을 끕니다. |
| "연결 중…"에서 멈춰요 | Play를 껐다 켰는데 자동 시작이 꺼져 있으면 서버가 꺼진 상태입니다. Start를 누릅니다. |
| QR 을 찍었는데 폰에서 페이지가 안 열려요 | ① 폰과 PC 가 같은 Wi-Fi(같은 공유기)인지. 폰이 모바일 데이터(LTE/5G)면 안 됩니다 ② 창의 **Windows 방화벽** 구역이 "막고 있습니다"면 **[방화벽 허용…]** ③ 창의 **이 PC 주소** 목록에서 폰과 같은 공유기 쪽 주소를 고르기 ④ 폰이 USB 로 꽂혀 있으면 **[연결 점검]** 으로 실제로 닿는지 확인 ⑤ 급하면 "QR 이 안 될 때: USB" 의 버튼을 씁니다 |
| 폰 카메라가 QR 을 못 읽어요 | **[QR 크게]** 를 누르고, 모니터 밝기를 올리고, 폰을 30~50cm 거리에서 QR 전체가 화면에 들어오게 비춥니다. Unity 창이 다른 창에 가려 QR 둘레의 흰 여백이 잘리면 못 읽습니다 |
| 앱에 "이 QR 은 더 이상 쓸 수 없습니다"나 "PC를 확인할 수 없습니다"가 떠요 | PC 에서 [새 QR 발급]을 눌렀거나 `Library` 폴더를 지운 경우입니다. 앱의 [QR 스캔] 또는 폰 카메라로 창의 QR 을 다시 찍습니다 |
| 폰에 "다른 기기가 보고 있습니다"가 떠요 | 화면은 한 기기에만 나갑니다. 이 기기에서 보려면 **[여기서 보기]** 를 누릅니다 |
| 예전의 "Wi-Fi 접속 허용"이 안 보여요 | 없앴습니다(0장 "없어진 것"). QR + 앱 또는 무선 adb(2.3절)를 씁니다 |
| 화면이 끊기거나 느려요(Wi-Fi) | JPEG Quality를 60~70으로 낮춥니다. 가능하면 USB를 씁니다. |
| 터치 반응이 한 박자 늦어요 | 창에서 **저지연 리드백**이 켜져 있는지 확인합니다(기본 켬). Latency 줄에 "저지연 잠시 중지"가 보이면 GPU가 바쁜 상태입니다(Scene 뷰를 닫으면 나아짐). FPS Cap이 낮으면(예: 30) 그만큼 늦어집니다. |
| 화면 일부가 검게 찢어져 보여요 | 예전 버전 페이지의 문제였고 **해결됐습니다**(원인: 캔버스 `desynchronized` 옵션 + 매 프레임 전체 검정 칠, 개발 문서 11장). 그래도 보이면 폰 페이지가 예전 것일 수 있으니 **새로 고침**합니다. 계속되면 `?debug=1`로 열어 왼쪽 위 `check ... black/jpeg/decErr` 숫자와 창의 `Frame check` / `Client check` 줄을 확인해 알려 주세요. |
| 터치할 때만 끊겨 보여요 | 손가락이 닿아 있는 동안 Chrome이 영상 수신을 미루던 문제로, 영상을 워커에서 받게 고쳤습니다(기본 켬, 개발 문서 12.9). 폰 페이지가 예전 것이면 새로 고치세요. 그래도 보이면 창에서 "테스트 패턴"을 켜고 네모가 고르게 움직이는지, `?sched=0`과 비교해 보세요. 네모는 고른데 게임만 끊기면 Unity 쪽입니다(창 `Pacing` 줄의 `hitches`) |
| 화면이 가끔 끊겨요(뚝뚝 끊김) | ① **FPS Cap을 Unity fps 이상**(기본 60)으로 둡니다. 낮으면 2프레임마다 1번 보냅니다 ② JPEG Quality를 60~70으로 낮춥니다(USB 대역폭 · 폰 디코딩 부담이 줄어 더 자주 보냄) ③ 창 `Pacing` 줄에서 `send`/`phone` 버림, `hitches`/`GC`를 봅니다. `hitches`가 오르면 Unity 자체가 멈춘 것(Game 뷰에서도 같이 멈춤)입니다. 폰에서는 `?debug=1` 왼쪽 위 `gap max`. 자세한 내용은 개발 문서 12장 |
| 화면이 멈췄어요(검지는 않음) | 폰 화면 아래 "화면이 멈춤" 경고를 봅니다. Game 뷰 탭이 가려졌으면 창의 "Game 뷰 보이기"를 누릅니다. Play 일시정지면 풉니다. |
| 버튼이 안 눌려요 | 창의 Clients에 `input 1`이 있는지 확인합니다. 0이면 페이지를 새로 고칩니다. |
| 포트 열기 실패 | 다른 프로그램이 7300을 쓰고 있습니다. Port를 바꾸고 `adb reverse`도 새 포트로 다시 누릅니다. |

방화벽을 손으로 열 필요는 없습니다. 창의 **[방화벽 허용…]** 버튼이 필요한 규칙만 넣고, **[되돌리기]** 가 원래대로 돌립니다.
